# Review Checker

Отслеживание отзывов Steam-игры: сбор всех отзывов через публичный
`appreviews` API, эвристический анализ на предмет накрутки/ботоферм
(playtime на момент отзыва, бесплатные ключи, повторяющийся текст,
всплески активности), и статический дашборд на GitHub Pages для
фильтрации, сортировки и визуализации.

Никакого бэкенда — GitHub Actions по расписанию собирает данные и
коммитит JSON в `docs/data/`, GitHub Pages отдаёт статику, которая
читает эти JSON прямо в браузере.

## Быстрый старт

1. **Форкни / склонируй репозиторий.**

2. **Укажи appid игры.**
   Settings → Secrets and variables → Actions → вкладка **Variables** →
   добавь переменную репозитория:
   - `STEAM_APPID` — например `4369490`
   - `STEAM_APPNAME` — опционально, отображаемое имя игры

3. **(Рекомендуется) Добавь Steam Web API ключ для обогащения данных об аккаунтах.**
   Получи бесплатный ключ на https://steamcommunity.com/dev/apikey (нужен
   любой Steam-аккаунт с телефоном, привязанным к нему).
   Settings → Secrets and variables → Actions → вкладка **Secrets** →
   New repository secret:
   - Name: `STEAM_WEB_API_KEY`
   - Value: твой ключ

   Без этого секрета всё остальное продолжит работать как раньше —
   просто не будет данных о возрасте аккаунта, приватности профиля и
   размере библиотеки игр автора отзыва (см. "Что даёт обогащение" ниже).

4. **Включи GitHub Pages.**
   Settings → Pages → Source: **Deploy from a branch** → Branch: `main`,
   folder: `/docs` → Save.

   (Раньше здесь использовался Source "GitHub Actions" с отдельным
   деплой-workflow'ом, но "Deploy from a branch" публикует изменения
   в `docs/` быстрее и без отдельной очереди деплоя — как только
   `fetch-reviews.yml` коммитит новые данные, Pages сама подхватывает
   их из ветки.)

5. **Запусти сбор данных вручную первый раз.**
   Actions → workflow **"Fetch Steam reviews"** → Run workflow.
   Он соберёт все отзывы, посчитает suspicion score и закоммитит
   `docs/data/latest.json` + снапшот в `docs/data/snapshots/`.

6. Публикация происходит автоматически при каждом коммите в `docs/`
   (Pages сам следит за веткой) — никакого отдельного деплой-шага
   ждать не нужно.

После этого данные будут обновляться каждые 12 часов автоматически
(cron в `.github/workflows/fetch-reviews.yml`, можно поменять частоту).

После каждого запуска (ручного или по расписанию) на странице запуска
в Actions появляется **Summary** — markdown-сводка с числом собранных
отзывов, флагами, топ-причинами и таблицей метрик, без необходимости
разворачивать логи каждого шага.

## Что даёт сверка с официальными данными Steam (`fetch_steam_summary.py`)

Помимо собранной нами выборки отзывов, скрипт дополнительно дёргает два
отдельных, независимых от нашей пагинации, публичных эндпоинта Steam:

- **`query_summary`** — общий счётчик Steam по *всем* отзывам игры на
  всех языках, и отдельно за последние 30 дней. Позволяет увидеть,
  какую долю всех отзывов реально покрывает наш сбор, и сравнить нашу
  выборку с официальным "recent reviews" рейтингом Steam — если наш
  % позитива сильно отличается от официального recent-рейтинга, это
  сигнал, что либо сбор неполный, либо ситуация изменилась совсем
  недавно.
- **`appreviewhistogram`** — дневная статистика отзывов, которую считает
  сам Steam. По ней вычисляется скорость поступления отзывов в неделю
  к неделе и аномальные дни-всплески — это работает, даже если наша
  собственная пагинация ещё не дошла до старых отзывов, потому что
  Steam считает эти цифры сам, независимо от нашего сбора.

Эти данные попадают в `docs/data/latest.json` (поля `steam_official_*`
в `summary`) и отображаются отдельной панелью на дашборде.

## Что ещё добавлено в suspicion score

- **Отзыв отредактирован спустя дни** — позиция могла смениться (например,
  после получения ключа или компенсации от разработчика).
- **Низкосодержательный текст** — позитивный отзыв из 1-2 слов ("10/10",
  эмодзи и т.п.). Сам по себе не доказательство, но в сочетании с другими
  сигналами усиливает картину.
- **Много votes при пустом тексте** — если короткий малосодержательный
  отзыв набрал много "helpful"-голосов, вероятно накручены и голоса тоже.

## hitlist.json — готовый список для ручной проверки

`build_snapshot.py` дополнительно пишет `docs/data/hitlist.json` — топ-100
самых подозрительных отзывов (score ≥ 40) с прямыми ссылками на профили
авторов, отсортированные по убыванию score. Удобно, чтобы не фильтровать
вручную полный `latest.json`, а сразу открыть готовый список для проверки
или подачи жалобы в Steam.

## Локальный запуск скриптов

```bash
cd scripts
python fetch_reviews.py --appid 4369490 --out ../data/raw_reviews.json --sleep 1

# независимая сверка с официальными данными Steam (быстро, 2-3 запроса):
python fetch_steam_summary.py --appid 4369490 --out ../data/steam_summary.json

# опционально, но сильно повышает точность обнаружения накрутки:
python enrich_accounts.py --in ../data/raw_reviews.json \
    --out ../data/enriched_reviews.json --api-key YOUR_STEAM_WEB_API_KEY
# без ключа просто копирует файл без изменений — можно пропустить этот шаг
# и подать raw_reviews.json прямиком в analyze.py

python analyze.py --in ../data/enriched_reviews.json --out ../data/analyzed_reviews.json
python build_snapshot.py --in ../data/analyzed_reviews.json \
    --appid 4369490 --appname "Название игры" \
    --latest-out ../docs/data/latest.json \
    --snapshot-dir ../docs/data/snapshots \
    --steam-summary ../data/steam_summary.json
```

## Что даёт обогащение через Steam Web API (`enrich_accounts.py`)

Помимо данных из `appreviews`, скрипт дополнительно тянет по каждому
уникальному автору отзыва:

- **Дату создания аккаунта** (`GetPlayerSummaries`) — если аккаунту
  меньше 7 дней и он уже успел похвалить игру, это самый сильный
  индивидуальный сигнал накрутки из всех, что есть в проекте.
- **Приватность профиля** — фермы/боты чаще держат профиль закрытым.
- **Общее число игр в библиотеке и суммарный playtime по всем играм**
  (`GetOwnedGames`) — аккаунт с 1-2 играми в библиотеке, одна из
  которых — та самая, которую он хвалит, выглядит подозрительно иначе,
  чем аккаунт с сотней игр.

Эти поля появляются в отзывах только если шаг обогащения реально
выполнился (нужен ключ) — без него всё работает как раньше, просто без
этой части данных, и соответствующие карточки на дашборде скрываются
автоматически.

Учти: `GetOwnedGames` дёргается по одному steamid за раз (у Steam нет
батч-версии этого метода), поэтому на играх с большим числом уникальных
авторов отзывов этот шаг — самый долгий в пайплайне. Для контроля
используй `--max-authors` при первых тестовых прогонах.

Открой `docs/index.html` через любой локальный HTTP-сервер
(`python -m http.server` в папке `docs/`) — `fetch()` не работает
с `file://`.

## Как считается suspicion score

Эвристика 0–100, сумма независимых сигналов:

| Сигнал | Вес |
|---|---|
| Позитивный отзыв, 0 минут наиграно на момент отзыва | +40 |
| Позитивный отзыв, <30 мин | +30 |
| Позитивный отзыв, <1ч | +15 |
| Бесплатный ключ, не куплено в Steam | +15 |
| Автор: ≥50 отзывов при ≤3 играх в библиотеке | +20 |
| Текст входит в кластер из ≥3 почти одинаковых отзывов | +25 |
| Отзыв опубликован в день аномального всплеска активности | +10 |
| Негативный отзыв, 0 часов наиграно | +5 |
| Отзыв отредактирован спустя >3 дней после публикации (позиция могла смениться) | +8 |
| *(нужен `enrich_accounts.py`)* Позитивный отзыв, аккаунту < 7 дней на момент отзыва | +25 |
| *(нужен `enrich_accounts.py`)* Позитивный отзыв, аккаунту < 30 дней | +12 |
| *(нужен `enrich_accounts.py`)* Приватный профиль | +10 |
| *(нужен `enrich_accounts.py`)* Позитивный отзыв, во всей библиотеке ≤2 игры | +15 |
| Позитивный отзыв, текст ≤2 слов | +10 |
| ≥20 votes_up при тексте ≤3 слов | +12 |

Это **не доказательство** накрутки — только сигнал для ручной проверки.
Дубликаты текста ищутся через word-shingling + Jaccard similarity
(без внешних зависимостей). Всплески дней определяются как дни с
объёмом отзывов ≥ 3× медианы по датасету.

## Структура

```
scripts/
  fetch_reviews.py     — сбор через Steam appreviews API (пагинация, ретраи)
  fetch_steam_summary.py — независимая сверка: официальный query_summary + histogram velocity
  enrich_accounts.py   — опционально: данные об аккаунтах авторов через Steam Web API
  analyze.py           — категоризация, suspicion score, дедупликация текста
  build_snapshot.py    — агрегаты + история снапшотов + hitlist.json для сайта
docs/
  index.html, app.js, style.css  — статический дашборд (без сборки, без фреймворков)
  data/latest.json               — актуальный полный срез (перезаписывается)
  data/snapshots/YYYY-MM-DD.json — лёгкие дневные снапшоты для графика истории
.github/workflows/
  fetch-reviews.yml    — cron сбор + коммит данных (публикация сайта происходит
                          автоматически через Pages "Deploy from a branch",
                          отдельный деплой-workflow не нужен)
```

## Известные ограничения

- Steam может ужесточать rate limiting — при больших играх (100k+
  отзывов) увеличь `--sleep` в workflow или разбей сбор на несколько
  запусков через `--since-id` (инкрементальный режим).
- `duplicate_text_cluster` детектор — O(n²) в худшем случае на уровне
  грубых bucket'ов по длине текста; для очень больших датасетов (десятки
  тысяч отзывов) может потребоваться MinHash/LSH вместо прямого сравнения.
- Дашборд хранит steamid авторов в открытом JSON (то же самое, что видно
  и на самой странице Steam) — если это нежелательно, хэшируй/убирай поле
  `steamid` в `fetch_reviews.py` перед сохранением.
